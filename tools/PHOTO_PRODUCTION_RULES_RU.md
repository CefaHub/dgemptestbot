# DOLCE EMPIRE — производство уникальных реальных фотокарточек

Дата сверки: 2026-10-20. Актуальные количества определяются командой `python tools/photo_production.py status`, а не этим файлом.

## 1. Цель и текущий остаток

Актуальный срез каталога на 19.10.2026 (сверен с `data/catalog.json` и `assets/collections/verified_sets.json`): **58 выпущенных карточек, 12 полных коллекций**, до базовых 100 осталось **42 фото в 8 полных альбомах**. Последний игровой релиз — **IVE / SPOTLIGHT / EPIC**, 6 фото. Уже опубликованные IVE AURA/EPIC и LE SSERAFIM AURA/EPIC/LEGENDARY/MYTHIC нельзя повторно выдавать за новые кадры.

План 100 фотографий — базовая очередь из 5 групп (ILLIT, aespa, IVE, ITZY, LE SSERAFIM) по четырём редкостям. Просьба **«ещё 100 новых фотографий поверх выпущенных»** означает отдельный этап расширения, а не существующую квоту: его нельзя имитировать переименованием или повторной обработкой старых кадров.

Не полагаться на статические числа документа после новых релизов: запускать `python tools/photo_production.py status` и проверять игровой каталог.

## 2. Обязательное качество

1. Только реальные фотоснимки участниц, не AI-генерация и не синтетические портреты. Фото с неподтверждёнными правами не публикуются.
2. **Один альбом = одна цельная фотосессия/редакционная коллекция.** У всех участниц сета единый `photo_session_id`, совпадающая концепция, свет, стилистика и доказуемые страницы источников. Название коллекции само по себе не доказывает общую съёмку.
3. **Не начинать изготовление карточек из фотосессии вообще**, пока уже не найден и не проверен полный комплект доступных, разных фотографий **всех** участниц. 4/5, 4/6 и 5/6 — отбрасываем весь кандидат, не готовим даже частичные исследовательские превью. Полный состав группы обязателен ДО первого рендера.
4. Одно исходное фото — одна карточка навсегда, включая остальные редкости. Дубли по URL, страницам, SHA-256 и близким perceptual hash отклоняются.
5. Каждая карточка — сольный кадр. Если исходник групповой, нужны качественный индивидуальный кроп `solo_region` и отдельное человеческое подтверждение `solo_review_status=approved`. Не обрезать лица/головы.
6. Реальный исходный кроп должен оставлять **не менее 600×800 пикселей**, включая кадрирование после зума. Нельзя ухудшать разрешение и затем выдавать апскейл за HD.
7. Картинка на выходе — **900×1200 (3:4)**, баннер — **1600×900 (16:9)**. Только пропорциональный cover-crop без растяжения.
8. Баннер составляется из тех же проверенных сольных кадров, что и карточки; никаких посторонних участников на краях.
9. Обязательны `source_page`, `photographer`, `license`, `license_url`, `license_status=verified`. Проверять конкретные условия коммерческого использования, атрибуции и ShareAlike до утверждения. Участницы не утверждают и не рекламируют проект.
10. Для публикации у сета требуется `collection_review_status=approved`. Поля прав/одобрения нельзя заполнять автоматически по аналогии со старым сетом.

## 3. Именование и неизменность идентификаторов

- `set_id`: `coll_{group_slug}_{era_slug}_{rarity}`
- `card_id`: `card_{group_slug}_{era_slug}_{rarity}_{member_lower}_{NN}`
- изображение: `assets/cards/{group_slug}/{group_slug}_{era_slug}_{rarity}_{member_lower}_{NN}.png`
- баннер: `assets/banners/{group_slug}/{group_slug}_{era_slug}_{rarity}_banner.png`

Индексы `NN` идут в утверждённом порядке участниц из `tools/photo_release_plan.json`, не в порядке поиска фото.

## 5. Рабочие команды

```bash
python tools/photo_production.py status
python tools/photo_production.py status --json
python tools/photo_production.py validate
python tools/photo_production.py template --set coll_lesserafim_aura_rare
```

Последняя команда создаёт **непубликуемый** черновик в `output/`. В нём пустые URL и права с состоянием pending. После наличия **ВСЕХ** оригиналов, проверки реальных фотографий, лицензий и общего `photo_session_id` можно подготовить релизный манифест. При одном недостающем кадре группа полностью пропускается.

Только для **полностью заполненного** манифеста:

```bash
python tools/photo_release_pipeline.py build --manifest tools/photo_releases.json
```

Без `--publish` будет лишь предварительная сборка в `output/photo_release_batch/`. После отдельной визуальной и юридической проверки допускается явная публикация `--publish` либо защищённый релизный процесс CI.

Все статусные и production-файлы — **планирование**, не полноценная публикация карточек. `tools/photo_releases.json` остаётся пустым, пока нет полного проверенного сета.
